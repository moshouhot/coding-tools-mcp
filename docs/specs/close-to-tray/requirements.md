# 需求文档：close-to-tray

## 功能概述

关闭主窗口时不再直接退出进程（否则 MCP / Actions / 隧道一并断开），而是**直接最小化到系统托盘**（隐藏窗口，服务继续），不弹任何确认框。真退出由托盘菜单「退出」承担。托盘可恢复窗口或退出。对应 GitHub #8。

> **行为变更（v0.2.4-custom.7）**：原设计为关窗弹三按钮确认（取消 / 后台运行 / 直接关闭）。
> 每次关窗都要做一次选择成本过高，用户要求取消弹窗、直接最小化。
> 语义收敛为：**窗口关闭 ≠ 退出程序**，退出只走托盘菜单。

## 历史经验与坑（来自记忆库）

- **可复用经验**: 已有 `UI_RECREATING` + keepalive + `ExitRequested.prevent_exit`，证明「无 UI 窗口时进程可继续」。托盘隐藏是同一意图的用户可见形态。
- **必须规避的坑**:
  1. 退出路径禁止在 async worker 里嵌套 `block_on`（跨项目 shutdown 卡死经验）；托盘「退出」应直接 `app.exit` / 关闭窗口，不做重清理。
  2. `recreate_ui_webview` 销毁主窗时不得被「关窗→弹确认/hide」拦住；销毁后若原先是托盘隐藏态，重建后应继续隐藏，禁止自动抢焦点弹出。
  3. Windows 最小化几何哨兵坐标问题已在 0.1.32/33 修过；托盘用 `hide`/`show`，不要误用 minimize 语义混用。

## 术语定义

- **后台运行**: 隐藏主窗口，保留托盘图标与全部后台服务。
- **直接关闭**: 结束桌面进程（服务随进程退出）。
- **托盘**: Windows 通知区域 / macOS 菜单栏状态项。

## 范围边界

**In Scope（本次要做）**
- 点窗口关闭（X）→ 阻止默认退出 → 直接 hide 主窗到托盘，**不弹确认框**。
- 托盘「退出」：真退出，不再二次确认。
- 托盘：左键显示并聚焦主窗；菜单「显示窗口」「退出」（退出不弹确认）。
- `recreate_ui_webview` 与托盘隐藏态协同：重建后若应保持隐藏则继续 hide。
- Windows / macOS。
- 二次启动：若已有实例在托盘，尽量唤起主窗（Windows 单实例路径）。

**Out of Scope（本次不做）**
- 「关闭时总是后台 / 总是退出」的持久偏好设置（可后续加）。
- Linux 托盘正式支持与打包验证。
- 自定义托盘独立图标资源（可用默认窗口图标）。
- 关闭时优雅停止各工作区 runtime 的独立进度 UI。

## 需求列表

### FR-1: 关窗直接最小化到托盘

**优先级:** Must

#### 验收标准（EARS）

1. WHEN 用户点击主窗口关闭按钮 THEN 系统 SHALL 阻止默认退出并把窗口隐藏到托盘，**不展示任何确认对话框**。
2. WHEN 窗口已隐藏 THEN MCP / Actions / 隧道 SHALL 保持运行。
3. IF 隐藏失败 THEN 系统 SHALL 保留原窗口，不得出现"已阻止关闭但未隐藏"的不一致状态。

### FR-2: 托盘恢复

**优先级:** Must

#### 验收标准（EARS）

1. WHEN 窗口已隐藏到托盘 THEN 系统 SHALL 保持托盘图标可见。
2. WHEN 用户左键点击托盘图标或选择「显示窗口」THEN 系统 SHALL 显示并聚焦主窗口。

### FR-3: 真退出

**优先级:** Must

#### 验收标准（EARS）

1. WHEN 用户从托盘菜单选择「退出」THEN 系统 SHALL 退出应用进程且不再弹出确认。
2. WHEN 用户点击窗口关闭按钮 THEN 系统 SHALL **不**退出进程（仅隐藏）。

### FR-4: 与 UI 重建协同

**优先级:** Must

#### 验收标准（EARS）

1. WHEN `recreate_ui_webview` 销毁并重建主窗 THEN 系统 SHALL 不因关窗拦截逻辑而失败。
2. IF 重建开始前主窗处于托盘隐藏态 THEN 重建完成后系统 SHALL 保持隐藏（不得自动弹出抢焦点）。
3. IF 重建开始前主窗可见 THEN 重建完成后系统 SHALL 恢复为可见可聚焦窗口（现有行为保留）。

### FR-5: 二次启动唤起（Windows）

**优先级:** Should

#### 验收标准（EARS）

1. WHEN 已有实例在运行（含托盘隐藏）且用户再次启动应用 THEN 系统 SHALL 尽量显示并聚焦已有主窗口，而不是静默失败无反馈。

---

## 非功能需求

- **NFR-1**: 关窗确认与托盘操作不得阻塞或停止 MCP/隧道 supervisor。
- **NFR-2**: 「直接关闭」/托盘退出应在数秒内结束进程，避免「正在关闭」卡死。
- **NFR-3**: 关窗后用户必须仍能通过托盘恢复窗口，不得出现"无法找回窗口"的状态。

## 依赖关系

- 依赖 Tauri 2 `tray-icon` feature 与现有 `tauri-plugin-dialog`（仅其它场景使用，本功能确认框为应用内 UI）。
- 依赖现有 `commands/ui_memory.rs` 的 `UI_RECREATING` / keepalive 机制，扩展隐藏态恢复。
- 依赖 Windows 现有 `CreateMutexW` 单实例逻辑，扩展唤起事件。

# 需求文档：tray-status-autostart

## 功能概述

为桌面端托盘补上两项能力：

1. **状态图标**：托盘图标只有两态——有 MCP 实际在监听时用**原图标**，否则用**灰度图标**；并在 tooltip 与状态菜单行给出文字细节，避免只靠颜色传达信息。
2. **开机自启并启动 MCP/隧道**：托盘右键新增一个勾选项。开启后写入 Windows 登录自启，登录时静默驻留托盘并自动启动**绑定工作区**的 MCP（复用既有隧道联动）。关闭只取消自启与绑定，不停止正在运行的服务。
3. **记住上次运行状态**：退出后再启动 EXE 时，自动恢复上次**实际在运行**的 MCP（按工作区），复用既有隧道联动。

设计参考：另一独立桌面工具的托盘实现（HKCU Run 自启 + 图标反映状态），本项目按本文档的验收标准独立实现。

> 图标仅两态，**不做重新着色**：运行中保持原作者图标样式，未运行转灰度。

## 历史经验与坑（来自记忆库）

- **可复用经验**: 既有 `setup_tray` 已实现「左键显示窗口 + 菜单显示窗口/退出」，本次只做增量；隧道联动已由 `tunnel/access.rs::maybe_start_for_runtime` 提供，启动 MCP 即自动连隧道，无需另写隧道逻辑。
- **必须规避的坑**:
  1. **不能把「保存过的公网 URL」当作隧道在线**。必须查隧道监督器的实际会话/进程存活（`TunnelSupervisor::status` → `running`）。
  2. **不能把「有工作区」等同于「有可启动目标」**。绑定工作区被删除后必须显式报错并跳过，绝不静默改启动其它工作区。
  3. **注册表写入失败必须可见**。不能因为 `set_value` 失败仍把菜单勾成「已开启」，勾选状态必须以注册表实际读回结果为准。
  4. 状态轮询不得持同步状态锁跨 `await`（此前 FRP 清理踩过）；采样应短、串行、可重入保护。
  5. 颜色不能是唯一状态载体（无障碍 + 深浅色主题），必须有文字与 tooltip。

## 术语定义

- **状态图标**: 托盘通知区域的图标。运行中=原图标，未运行=灰度图标。
- **绑定工作区**: 开机自启时被启动 MCP 的那个工作区，记录在 `autostart_workspace_id`。
- **上次运行状态**: 最近一次观测中**确实在监听**的 MCP 工作区集合，记录在 `running_mcp_workspace_ids`。记录的是真实观测值，而非「用户点过启动」的意图。注意它不保证零丢失：两次观测之间（最长 5 秒）的变化可能来不及落盘。
- **健康**: MCP 运行中；若该工作区配置了隧道，则隧道也确认在线。
- **隧道未连（TunnelOffline）**: MCP 运行中但隧道未连上。
- **MCP 错误（McpError）**: MCP 自身未能监听端口 / 启动失败。**不计入运行中**，与隧道问题区分展示。

## 范围边界

**In Scope（本次要做）**

- 托盘图标两态（运行中=原图标，未运行=灰度）+ tooltip 多行明细 + 只读状态菜单行。
- 5 秒串行轮询，仅在状态变化时更新图标。
- 托盘右键勾选项「开机自启并启动 MCP/隧道」；仅在**多工作区**时附加 `（<工作区名>）`，单工作区下名称冗余，不显示。
- HKCU Run 自启项（`CodingToolsMcpDesktop`），命令为带引号的当前 exe 路径 + `--autostart`。
- `--autostart` 启动路径：隐藏窗口、驻留托盘、后台启动绑定工作区的 MCP。
- 普通启动路径：恢复上次实际在运行的 MCP 工作区（与 `--autostart` 路径**互斥**）。
- 运行状态在**变化时**记录，而不是只在退出时快照（退出快照只在正常退出路径执行，崩溃/强杀/断电下会缺失）。
- 启动/停止/重启等**真实转换**完成后立即记录，不等下一轮轮询；内部重启的临时停止不写入。
- 绑定工作区持久化、失效检测与显式报错。

**Out of Scope（本次不做）**

- 不启动 Actions 服务（自启只针对 MCP）。
- 不做「启动全部工作区」。
- 不做真正的系统级托盘气泡通知（失败通过系统错误对话框展示，成功只记日志）。
- 不改动前端界面（本次为托盘 + Rust 侧能力）。
- 不新增第三方依赖（自启用已启用的 `windows` crate 的 Registry feature）。
- 不改动参考项目。

## 验收标准

1. 无工作区时图标为灰，tooltip 说明「尚未添加工作区」。
2. 至少一个 MCP 确实在监听 → 原图标；否则 → 灰度。启动中 / MCP 错误 / 隧道未连**不改变图标**，只体现在文字里。
3. **MCP 错误不得计为运行中**，也不得展示成「运行中 · 隧道未连接」。
4. 勾选开启后：HKCU Run 出现 `CodingToolsMcpDesktop`，值等于 `"<exe>" --autostart`；菜单显示绑定的工作区名。
5. **开启只绑定用户明确选中的工作区**；未选中时提示并拒绝，**不回退到首个工作区**。
6. 开启过程中写入失败、绑定保存失败、读回不匹配**任一失败都回滚到旧状态**；
   回滚不完整时错误信息必须明确报告。
7. 注册表**读取失败不得当成「未启用」**：读取失败时取消操作并报错；
   关闭流程中读取失败必须**保留绑定**。
8. 关闭勾选：**删除后读回确认已不存在**才清绑定；删除失败 / 读回仍存在 / 无法判定
   均报错并保留绑定；全程**不停止**正在运行的 MCP/隧道。
9. **不触碰其它应用**的 Run 项。
10. 带 `--autostart` 启动：窗口隐藏、托盘存在、绑定工作区的 MCP 被拉起并复用隧道联动。
11. **绑定工作区已被删除时，`--autostart` 必须提示并跳过，绝不启动其它工作区**（不得回退到 last/first）。
12. 隧道已配置但未连上时，自启提示必须表达为部分成功，不得宣称「MCP 与隧道已启动」。
13. 失败必须写入**不被 5 秒轮询覆盖**的可见出口（系统错误对话框），不能只写会被覆盖的 tooltip 或 release 下不可见的 stderr。
14. 含空格、中文或超长安装路径下自启命令仍然正确（引号包裹且成对）。
15. 图标仅在档位变化时更新（避免每 5 秒无谓重绘）。
16. 非 Windows 平台不展示自启菜单项。
17. 所有新增单元测试通过；`cargo clippy` 在新增/修改文件中无警告。
18. **普通启动时自动恢复上次实际在运行的 MCP**：上次有 MCP 在跑 → 启动后自动拉起；上次全部停止 → 不启动任何服务。
19. **恢复只针对上次确实在监听的工作区**：启动中 / MCP 错误 / 已停止都不得被记成运行，否则会误恢复。
20. **恢复绝不回退**：上次运行的工作区已被删除时直接丢弃，不拿其它工作区顶替；全部失效时什么也不启动。
21. **两条启动路径互斥**：`--autostart` 只启动绑定工作区（不读历史运行集合），普通启动只恢复历史运行集合（不读自启绑定）。
22. **启动动作期间暂停记录**：首轮采样早于服务拉起，不得把「当前为空」写回磁盘而抹掉待恢复集合。
23. **运行状态在变化时才落盘**：每 5 秒轮询不得反复写 `profiles.json`（内容未变则不写）。
24. 旧版 `profiles.json`（无 `running_mcp_workspace_ids`）必须能直接反序列化，无需迁移。
25. 恢复过程中部分失败（端口冲突、启动失败、隧道未连）必须汇总为一次可见提示，不得静默失败，也不得弹出多个对话框。
26. 恢复失败**不得影响窗口正常显示**（普通启动的窗口可见性不变）。
27. 退出时补一次**只读**快照，且不得在退出阶段修改监督器状态或 spawn 任务（可能 panic）。
28. **真实转换立即记录**：启动 / 停止 / 重启完成后立刻落盘，不等下一轮轮询。
29. **内部重启的临时停止不得被记录**：重启过程中暂停记录，保留原「运行中」状态；中途崩溃时下次会重试启动。
30. **过期样本不得落盘**：采样跨越一次启动转换（代次已变）时必须丢弃，否则旧快照会覆盖刚恢复的集合。
31. **读取失败不得当成空集合**：工作区 / 运行时 / 端口任一读取失败时保留原有记录，未知状态不抹掉历史。
32. **记录失败必须可见**：落盘失败要报告（同一失败片段只报一次，不每 5 秒弹窗），并写日志。
33. **恢复目标失效不得静默丢弃**：上次运行的工作区已被删除时，必须在失败报告中显式列出。
34. **记录写入须经 `DATA_FILE_LOCK`**：与仓库其它写入路径保持一致，避免并发写入互相覆盖。
